# Food Delivery Orders API

A small REST API for managing food delivery orders. It is built with JavaScript and the Next.js App Router, and provides endpoints for listing, creating, reading, updating, and deleting orders.

This project is intentionally lightweight and easy to run locally. It is suitable for learning, prototyping, or serving as a starting point for a production order service.

## Features

- Complete CRUD operations for food delivery orders
- JSON request and response bodies
- Validation for new orders
- Helpful HTTP status codes and JSON error responses
- Five sample orders available on startup
- Simple in-memory storage with no database setup required

## Tech Stack

- [Next.js](https://nextjs.org/) 14 with the App Router
- JavaScript
- React 18
- Node.js and npm

## Getting Started

### Prerequisites

- Node.js 18.17 or later
- npm

### Installation

Clone the repository and install its dependencies:

```bash
git clone https://github.com/sumitpriyadarshii/CRUD-api-.git
cd CRUD-api-
npm install
```

### Start the development server

```bash
npm run dev
```

The API is available at `http://localhost:3000`.

To create a production build and run it locally:

```bash
npm run build
npm start
```

## API Overview

All endpoints use the `/api/orders` base path and return JSON unless otherwise noted.

| Method | Endpoint | Description | Success status |
| --- | --- | --- | --- |
| `GET` | `/api/orders` | Return all orders | `200 OK` |
| `GET` | `/api/orders/:id` | Return one order by ID | `200 OK` |
| `POST` | `/api/orders` | Create a new order | `201 Created` |
| `PUT` | `/api/orders/:id` | Update an existing order | `200 OK` |
| `DELETE` | `/api/orders/:id` | Delete an order | `204 No Content` |

## Order Model

Each order has the following fields:

| Field | Type | Required for `POST` | Description |
| --- | --- | --- | --- |
| `id` | number | No | Automatically generated unique order ID |
| `customerName` | string | Yes | Name of the customer |
| `restaurant` | string | Yes | Restaurant fulfilling the order |
| `item` | string | Yes | Ordered food item |
| `amount` | number | Yes | Order amount; must be zero or greater |
| `status` | string | Yes | Current delivery status, such as `Pending` or `Delivered` |

Example order:

```json
{
  "id": 1,
  "customerName": "Aarav Sharma",
  "restaurant": "Spice Garden",
  "item": "Paneer Biryani",
  "amount": 14.99,
  "status": "Preparing"
}
```

## Using the API

The following examples use `curl`. In Windows PowerShell, use `curl.exe` instead of `curl` if the shell maps `curl` to `Invoke-WebRequest`.

### Get all orders

```bash
curl http://localhost:3000/api/orders
```

The response is an array of orders:

```json
[
  {
    "id": 1,
    "customerName": "Aarav Sharma",
    "restaurant": "Spice Garden",
    "item": "Paneer Biryani",
    "amount": 14.99,
    "status": "Preparing"
  }
]
```

### Get one order

Replace `1` with the ID you want to retrieve:

```bash
curl http://localhost:3000/api/orders/1
```

If the ID does not exist, the API returns:

```json
{
  "error": "Order not found"
}
```

### Create an order

Send all required fields as a JSON object. The `id` is generated by the API, so do not include it.

```bash
curl -X POST http://localhost:3000/api/orders \
  -H "Content-Type: application/json" \
  -d '{
    "customerName": "Alex Smith",
    "restaurant": "Pizza House",
    "item": "Large Pizza",
    "amount": 15.99,
    "status": "Pending"
  }'
```

The new order is returned with status `201 Created`.

### Update an order

Use `PUT` with the order ID. The API merges the submitted fields into the existing order, so you can send only the fields that need to change:

```bash
curl -X PUT http://localhost:3000/api/orders/1 \
  -H "Content-Type: application/json" \
  -d '{
    "status": "Out for delivery"
  }'
```

To update multiple fields at once:

```bash
curl -X PUT http://localhost:3000/api/orders/1 \
  -H "Content-Type: application/json" \
  -d '{
    "restaurant": "Pizza House",
    "item": "Large Pepperoni Pizza",
    "amount": 18.5,
    "status": "Preparing"
  }'
```

The updated order is returned with status `200 OK`. The order ID cannot be changed by the request.

### Delete an order

Replace `1` with the ID you want to delete:

```bash
curl -X DELETE http://localhost:3000/api/orders/1
```

A successful deletion returns `204 No Content` with an empty response body.

## Validation and Errors

When creating an order, the API checks that:

- `customerName`, `restaurant`, `item`, and `status` are strings
- `amount` is a number greater than or equal to zero
- All five required fields are present

Invalid create requests return `400 Bad Request` with an error message:

```json
{
  "error": "amount must be a non-negative number"
}
```

Requests for an invalid or missing order ID return `404 Not Found`:

```json
{
  "error": "Order not found"
}
```

## Data Storage

Orders are stored in an in-memory JavaScript array. The application starts with five sample orders, and changes remain available while the server process is running. Data is reset when the server restarts, so this implementation should not be used as permanent production storage without adding a database.
